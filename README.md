# Discord Server Mirror Tool - Node.js

Node.js環境で動作する、Discordサーバーの内容を別のサーバーに複製・中継するための高度なツールです。
チャンネル等の構造コピー用スクリプト(`webh_c.js`)と、リアルタイムのメッセージ内容転送やメッセージ変化(編集・削除)への対応用スクリプト(`webh.js`)の2つの機能から成り立っています。

## 必要要件
* **[Node.js v16 以上](https://nodejs.org/)**
* Discord トークン
   * 元サーバー(Source)にアクセス可能な「メッセージ読み取り用トークン (Userトークンなど)」
   * 先サーバー(Target)の権限を持つ「操作・構築用トークン」
   * ※ 本プログラム内部では User アカウントを使用する前提の設計 (Discord API V9 WebSocket仕様 等) が一部含まれています。
* 使用するモジュール: `discord.js`, `axios`, `ws`, `form-data`

## 📂 ディレクトリ構成
各種スクリプトと同じ階層に設定ファイルを配置してください。実行時に `logs` フォルダが自動生成されます。

```text
.
├── webh_c.js          <-- [機能1] チャンネル同期・作成用ツール本体
├── webh.js            <-- [機能2] メッセージ中継(ミラーリング)用ツール本体
├── webh_c.json        <-- webh_c.js の設定ファイル
├── webh.json          <-- webh.js の設定ファイル
├── proxies.txt        <-- プロキシリスト (任意 / 中継用)
└── logs/              <-- webh.jsの実行ログが最大10件自動保存されます
```

## 搭載されている全ての機能

### 1. サーバーの構造コピー機能 (`webh_c.js`)
移行先のサーバーにまっさらな状態から同じ構造を作り出す「ベース構築」ツールです。
* **チャンネル自動クローン**: 元サーバーのカテゴリーやチャンネル名を取得し、対象のサーバーへ同じ階層で再構築します。
* **権限設定・並び順維持**: 位置情報(`position`)やチャンネル個別の権限上書き設定(`permission_overwrites`)も可能な限り同期されます。
* **多彩なタイプに対応**: 通常のテキスト/ボイスチャンネルのほか、アナウンスやフォーラムなど幅広いタイプ(Type: 0, 2, 4, 5, 15)をサポートします。
* **429 レート制限回避**: API側から制限された場合、ペナルティ時間分だけ自動的に処理をスリープしリトライを実行します。

### 📡 2. メッセージリアルタイム中継機能 (`webh.js`)
2つのサーバーが同構造になったあとに利用する、中立型のミラーリング・プロキシbotです。
* **Websocket リアルタイム受信用 API V9接続**: 元サーバー内で動いているあらゆるアクションを瞬時に拾います。
* **自動Webhook生成**: マッチした構造の対象チャンネル側に中継用のWebhook(`MirrorForwarder`)がなければ、プログラムが自動で生成し再利用します。
* **完全なメッセージコピー対応**: 送信者のユーザー名(フォーマットや伏字の配慮)、ユーザーアイコンの転写を行い、内容だけでなく埋め込みデータ(Embed)、スタンプ(URLリンク化して表現)、別メッセージへのリプライやファイル（9.9MB以下のアップロード、超える場合のURL貼り付け変換）を丸ごと転送します。
* **編集(`MESSAGE_UPDATE`)と削除(`MESSAGE_DELETE`)に追従**: 一度送ったメッセージも専用マップメモリへ記録し続け、大本で修正や削除がされたら先のWebhookにも `(edited)` `(deleted)` として反映修正をかけます。
* **サーバー参加通知対応(`GUILD_MEMBER_ADD`)**: 対象ユーザーのプロフィールとともに独自の参加通知メッセージに書き起こして通知します。
* **構造変更自動追随`: コピー元や先で新しくチャンネルが生成されたり消去されるイベントが走った場合、チャンネル構成キャッシュデータを再取得する自己治癒の仕組みを持っています（`syncDebounceTimer`制御）。
* **API規制＆BAN対策保護ロジック**: 各Webhook発信時等にはランダムなIPによる `proxies.txt` 対応を行い、さらにはCloudflareなどによって弾かれたエラー (`cf-error`, `403`, `502`, `503` ステータスなど) に対し最大30秒単位でクールダウンを図ります。

## 設定ファイルの書き方
すべてUTF-8で保存してください。各項目は事前に構築してから使用します。

### 1. `webh_c.json` (コピー先構築用)
サーバー作成用の `webh_c.js` に使用される設定です。

```json
{
  "messageToken": "取得元のDiscord用トークン",
  "operatorToken": "構築用の操作を行う側のDiscord用トークン",
  "sourceGuildId": "取得・読取元のサーバーID",
  "targetGuildId": "生成先（ミラー先）となるサーバーID"
}
```

### 2. `webh.json` (リアルタイム中継用)
データ流し込み用の `webh.js` 用設定です。高度な紐づけ変更等が含まれます。

```json
{
  "botToken": "※(スラッシュコマンド機能などを利用する時のみのボットトークン)",
  "messageToken": "取得・読取元からの情報受信用トークン",
  "operatorToken": "構築用など、対象の権限を持つWebhook作成などをこなす側のトークン",
  "sourceGuildId": "取得・読取元のサーバーID",
  "targetGuildId": "転送対象（ミラー先）となるサーバーID",
  "channelIdOverrides": {
    "転送元の例外的なチャンネルID_1": "紐づけ先を名前やカテゴリ合致等で自動判別せず、手動指定する際のチャンネルID_A"
  },
  "allowedUserIds":[
    "スラッシュコマンドでの設定操作・再起動操作などを許された運営側ユーザーIDを文字列で記載します"
  ]
}
```

### 3. `proxies.txt` (任意設定)
リアルタイム中継時に送信を安定化・高速分散・プロテクト回避するためのProxyです。空でも（ファイル未作成でも）ローカルのネットワークを通って動きます。
```text
http://192.168.1.1:8080
10.0.0.1:3128:user:password
```

## 起動・使用方法

### セットアップ
使用するライブラリモジュールを一度にすべてインストールしてください。
```bash
npm install discord.js axios ws form-data
```

### STEP1: ベースのチャンネル群を作成する (webh_c.jsの実行)
1. まっさらな「生成先（Target）のサーバー」を準備してください。
2. ディレクトリ上でチャンネル構築ツールを単発実行します。
   ```bash
   node webh_c.js
   ```
3.  `Source server has ○○ channels, Target...` が現れ、完了時に `Channel synchronization finished successfully!` と出れば基盤の移行はすべて終了です。（終了後は自動で待機はしません。閉じられます。）

### STEP2: 常駐型リアルタイム・メッセージ・ミラーを行う (webh.jsの実行)
1. STEP1 で完全に同構造にできた対象間で実行を開始させます。
   ```bash
   node webh.js
   ```
2. 自動で元々の構成が合致・照合された上で、コンソールには `〇〇 channels mapped.` `Connected to WebSocket` が現れ準備状態になります。
3. ミラー中は止めない限り動き続けます。万が一切断が起きても一定間隔でRe-Sync（自動リセットからの再開復帰）を試行し常駐稼働を安定化します。

## ログの見方

`webh_c.js` については直接コンソールに進行内容(作成カテゴリ名・チャンネル名)が表示されます。
本運用の `webh.js` に関しては、ターミナル上に直接印字されるほか、ディレクトリ内の `.logs/` に英数ランダムファイル名(例:`a1b2c3d4-bot.log`)で全記録として同時記述され続け、最大「10世代まで」を限界にして古いものから整理自動消去されていく仕組みを持っています。

### ログ書式の具体例
* <span style="color:cyan">**[時刻・日時 (YYYY-MM-DD)]**</span> `〇〇 channels mapped.` 
   * マッピング成立状況、AutoMapによって対象チャンネルや特定権限構造がリンクされた状態等の一般情報。
* <span style="color:red">**ERROR:**</span> `[API] Blocked (403,502). Waiting 30s.` や API Rate Request / WebSocket closed 等 
   * Discord API（もしくはCFのNigger対策壁など）から制限、拒絶を受け失敗した際に通知。大抵自動的なRetryタイマーに乗ります。
* <span style="color:yellow">**WARN:**</span> などのテキスト
   * Webhookでのレート制限（Rate limitなど）を引っ掛けた一時的スローダウン時の確認などの状態通知として記述。
